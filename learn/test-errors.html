16.1 Big Test: Errors & try/except

25 questions on Errors and exceptions only, from basic to challenge. Try each one first, then open the answer. Back to the chapter.

  1. Basic. Type exactly what this code prints.

    Answer
    43

    Nothing goes wrong inside try, so the except block is skipped.

  2. Basic. text = "abc". Convert it to an int inside try. If that gives a ValueError, print Not a number.

    Your code should print exactly:

    Not a number
    Answer

    int("abc") raises ValueError. The except ValueError: block catches it and the program carries on.

  3. Basic. d = 0. Print 10 / d inside try, and print Cannot divide by zero if a ZeroDivisionError happens.

    Your code should print exactly:

    Cannot divide by zero
    Answer

    Name the exact error you expect after except.

  4. Basic. The starter has three small functions that each fail in a different way. Call each one inside try, and in except Exception as e: print the name of the error with type(e).__name__.

    Your code should print exactly:

    ValueError
IndexError
KeyError
    Answer

    Exception catches almost every error. type(e).__name__ gives its name: a bad conversion, an index past the end, a missing key.

  5. Basic. This code should print Cannot divide, but it crashes. Fix the except line.

    It should print:

    Cannot divide
    Answer

    except ValueError only catches a ValueError. Dividing by 0 raises ZeroDivisionError, so name that one.

  6. Basic. Type exactly what this code prints.

    Answer
    ok 5
done

    else runs when there was no error. finally runs every time, error or not.

  7. Basic. Write set_price(p) that raises ValueError("Price must be positive") when p is 0 or less, and returns p otherwise. Call set_price(0) inside try and print Error: Price must be positive.

    Your code should print exactly:

    Error: Price must be positive
    Answer

    raise creates the error yourself. except ... as e gives you the error, and printing e shows its message.

  8. Basic. This code should print hi. The try does not help here. Fix the real problem.

    It should print:

    hi
    Answer

    A syntax error stops Python before anything runs, so try cannot catch it. Only runtime errors can be caught. Close the bracket.

  9. Medium. readings = ["12.5", "x", "13", "--", "11.5"]. Convert each with float() inside try, skip the bad ones, and print the clean list and how many were skipped.

    Your code should print exactly:

    [12.5, 13.0, 11.5] 2
    Answer

    A try inside the loop handles each value on its own, so one bad value does not stop the rest.

  10. Medium. Type exactly what this code prints.

    Answer
    checked 2
5.0
checked 0
zero

    finally runs just before the function returns, so checked is printed before each result.

  11. Medium. Try int("12a"), catch it with except ValueError as e, and print Error: followed by the message.

    Your code should print exactly:

    Error: invalid literal for int() with base 10: '12a'
    Answer

    The error object carries Python's own message, which is handy in logs.

  12. Medium. Write safe_get(d, key) that returns d[key], or "missing" if that raises a KeyError. Print safe_get({"a": 1}, "a") and safe_get({"a": 1}, "b") with one print().

    Your code should print exactly:

    1 missing
    Answer

    A try inside a function can turn an error into a normal return value.

  13. Medium. This check should pass and print Check passed, because the total really is 60. Fix the assert.

    It should print:

    Check passed
    Answer

    assert stops the program with an AssertionError when its check is False. The check itself was wrong.

  14. Medium. Type exactly what this code prints.

    Answer
    A
C
D

    The error happens on the second line, so B is skipped. After the except block, the program carries on.

  15. Medium. Write withdraw(balance, amount) that raises ValueError("Insufficient funds") when amount is more than balance, and returns the new balance otherwise. For the pairs (500, 200) and (500, 800), print the result or Error: Insufficient funds.

    Your code should print exactly:

    300
Error: Insufficient funds
    Answer

    The function only reports the problem. The caller decides what to do with it.

  16. Medium. For each value in ["5", "x", None], try int(value) and print ok or bad. Catch both ValueError and TypeError in ONE except.

    Your code should print exactly:

    ok
bad
bad
    Answer

    int("x") is a ValueError and int(None) is a TypeError. A tuple after except catches both.

  17. Medium. This code should print Error: Negative age. Fix the raise line.

    It should print:

    Error: Negative age
    Answer

    You can only raise an error object, like ValueError("message"), not plain text.

  18. Medium. menu = {"tea": 20}. A traceback showed KeyError: 'coffee' from menu[item]. Write get_price(item) that returns the price, or 0 when the item is missing, using get() instead of try. Print get_price("tea") and get_price("coffee").

    Your code should print exactly:

    20 0
    Answer

    Reading the traceback tells you the line and the cause. Often the best fix avoids the error altogether.

  19. Challenge. Pretend the user typed typed = ["", "abc", "-3", "7"]. Go through them and find the first whole number from 1 to 10, using try/except ValueError and a range check. Print Invalid entry for each bad one, then OK: 7.

    Your code should print exactly:

    Invalid entry
Invalid entry
Invalid entry
OK: 7
    Answer

    Two kinds of bad input: text that is not a number (caught by except) and numbers out of range (caught by the if).

  20. Challenge. For each item in ["10", "20", "x", "30"]: convert it in try, count it as bad in except, and add it to the total in else. Then print the total, the number of bad items and the average of the good ones.

    Your code should print exactly:

    60 1 20.0
    Answer

    Keep the try block small (only the risky line). The work that should happen only on success goes in else.

  21. Challenge. Write parse_score(text): convert it with int() (let its ValueError happen), then raise ValueError("Out of range") if it is not from 0 to 100. For ["85", "105", "abc"], print the score or Error: with the message.

    Your code should print exactly:

    85
Error: Out of range
Error: invalid literal for int() with base 10: 'abc'
    Answer

    Both problems come out as a ValueError, so one except handles them, and the message says which one it was.

  22. Challenge. Type exactly what this code prints.

    Answer
    finally runs
try

    Even when try returns, finally still runs first. Then the returned value is printed.

  23. Challenge. This code should print 25.0, cannot divide by zero and not a number. Fix it so every value is handled.

    It should print:

    25.0
cannot divide by zero
not a number
    Answer

    One try can have several except blocks, one per kind of error.

  24. Challenge. Write to_number(text) that returns an int if it can, otherwise a float if it can, otherwise None (use a try inside an except). Print [to_number(x) for x in ["7", "7.5", "seven"]].

    Your code should print exactly:

    [7, 7.5, None]
    Answer

    Try the strictest conversion first. If it fails, fall back to the next one.

  25. Challenge. Write average(values) that uses assert to check the list is not empty (message No values), then returns the average. Call average([]) in try/except AssertionError as e and print Error: No values. Then print average([4, 6]).

    Your code should print exactly:

    Error: No values
5.0
    Answer

    assert is a quick way to state what must be true. When it fails, it raises AssertionError with your message.
