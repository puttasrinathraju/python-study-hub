Part 6 projects: classes and objects

Three small systems built from classes, the way business software is organised: an inventory, bank accounts, and a hotel booking desk. Each brief names the classes and methods to write. NumPy is not needed yet.

In the interactive version you write each program in the browser, run it with your own numbers, and press Submit to get an automatic score out of 100 with feedback. A score of 70 or more means you are ready for the next project.

Project 6.1 (Beginner): Stock inventory with a class

Model each product as an object with its own methods, then report on the stock.

Ramesh runs a stationery shop in Warangal and keeps his stock in a notebook. He wants a small program where every product is an object that knows its own price and quantity, can work out its own stock value, and can say whether it is running low.

Write a Product class, read the products until done, and print a stock report.

What you will practise

  • Write a class with __init__ and self
  • Give objects their own methods
  • Use __str__ to print an object nicely
  • Work with a list of objects

You may use: everything from Parts 1-5, class, __init__, self, methods and default values, __str__.
Do not use yet: NumPy (Part 7).

Your tasks

  1. Write class Product with __init__(self, name, price, qty) that stores the three values.
  2. Add value(self) that returns price × qty.
  3. Add is_low(self, limit=10) that returns True when qty is below the limit.
  4. Add __str__(self) that returns text like Pen: 120 x ₹10.00 = ₹1,200.00 (name, qty, price, value).
  5. Read rows name,price,qty until done (any capitals). Strip each part; the price can have paise (float), the qty is whole (int). Make a Product for each row and keep them in a list.
  6. If there are no products, print No products. Otherwise print each product (just print(product)), in the order they came.
  7. Then print Products, Stock value (the sum of every value()), Low stock (names joined with , , or none) and Most valuable (the product with the highest value; the first one if tied).

Lines your output must contain

<Name>: <qty> x ₹<price> = ₹<value>
Products: <count>
Stock value: ₹<amount>
Low stock: <names> or none
Most valuable: <Name> (₹<amount>)
No products

Money has ₹, commas and 2 decimals (:,.2f). Names are printed as typed, without the spaces around them.

Example run

Typed values: Pen,10,120, Notebook,45,30, Ink,25,8, done.

Product (name,price,qty) or done: Pen,10,120
Product (name,price,qty) or done: Notebook,45,30
Product (name,price,qty) or done: Ink,25,8
Product (name,price,qty) or done: done
Pen: 120 x ₹10.00 = ₹1,200.00
Notebook: 30 x ₹45.00 = ₹1,350.00
Ink: 8 x ₹25.00 = ₹200.00
Products: 3
Stock value: ₹2,750.00
Low stock: Ink
Most valuable: Notebook (₹1,350.00)

Edge cases to think about

  • done straight away: no products.
  • A quantity of exactly 10 is not low (below 10 is low).
  • The most valuable product is about price × qty, not the highest price.
  • Prices with paise.
  • Only one product.

Hint 1

Inside the class, every method starts with self, and every stored value is self.something. For example def value(self): return self.price * self.qty.

Hint 2

Make the objects in the loop: name, price, qty = [part.strip() for part in row.split(",")], then products.append(Product(name, float(price), int(qty))).

Hint 3

After the loop: sum(p.value() for p in products) for the stock value, [p.name for p in products if p.is_low()] for the low ones, and keep the best product so far with if p.value() > best.value():.

Project 6.2 (Intermediate): Bank accounts with rules

Build an Account class and a SavingsAccount that inherits from it, with rules that protect the balance.

A cooperative bank in Guntur wants a teaching version of its account system. Every account can take deposits and withdrawals, but money must never go wrong: no negative amounts, no withdrawing more than the balance. A savings account has two extra rules: it must keep at least ₹1,000, and it earns monthly interest at 4% a year.

Write the classes, then a small command loop where a clerk types commands like deposit 500 until done.

What you will practise

  • Protect data inside a class with checks and raise
  • Build a child class with inheritance and super()
  • Override a method to add a rule
  • Catch the errors in the main program

You may use: everything from Parts 1-5, class, inheritance, super(), raise and try / except, class attributes, properties.
Do not use yet: NumPy (Part 7).

Your tasks

  1. Write class Account with __init__(self, owner, balance=0). Keep the balance private (self.__balance or self._balance) and give a balance property or method to read it.
  2. deposit(amount) and withdraw(amount) raise ValueError("Amount must be positive") for 0 or less. withdraw raises ValueError("Insufficient funds") when the amount is more than the balance. Both return the new balance.
  3. Write class SavingsAccount(Account) with a class attribute rate = 4 (percent a year). Override withdraw so it raises ValueError("Minimum balance is ₹1,000.00") if the balance would go below ₹1,000, otherwise it calls super().withdraw(amount).
  4. Add add_interest() to SavingsAccount: interest = balance × rate ÷ 100 ÷ 12, rounded to 2 decimals; add it and return it.
  5. Ask for the owner's name, the account type (savings or current, any capitals) and the opening balance, then create the right object (current uses plain Account).
  6. Read commands until done: deposit <amount>, withdraw <amount>, interest. After each, print Deposited ₹500.00. Balance: ₹1,500.00 (or Withdrew ..., Interest ...), or Error: <message>. Other messages: Error: Amount must be a number, Error: Amount missing, Error: Interest is only for savings accounts, Error: Unknown command.
  7. At the end print Account: <owner> (<type>), Transactions: <successful commands> and Final balance.

Lines your output must contain

Deposited ₹<amount>. Balance: ₹<amount>
Withdrew ₹<amount>. Balance: ₹<amount>
Interest ₹<amount>. Balance: ₹<amount>
Error: <message>
Account: <owner> (<type>)
Transactions: <count>
Final balance: ₹<amount>

Money has ₹, commas and 2 decimals. The account type is printed in small letters. The checks happen in this order: amount missing, not a number, 0 or less, more than the balance, then the savings minimum.

Example run

Typed values: Asha, savings, 5000, deposit 2500, withdraw 1200, interest, done.

Deposited ₹2,500.00. Balance: ₹7,500.00

Command: interest
Interest ₹21.00. Balance: ₹6,321.00
Command: done
Account: Asha (savings)
Transactions: 3
Final balance: ₹6,321.00

Edge cases to think about

  • A withdrawal of more than the balance: Insufficient funds (for both kinds of account).
  • A savings withdrawal that would leave less than ₹1,000.
  • Interest on a current account.
  • Amounts that are words, 0 or negative, or missing.
  • An unknown command, and DONE in capitals.

In Account.withdraw: if amount <= 0: raise ValueError("Amount must be positive"), then if amount > self._balance: raise ValueError("Insufficient funds"), then subtract and return the balance.

Project 6.3 (Challenging): Hotel booking desk

Model rooms, suites and a hotel as classes, and run the front desk from typed commands.

A heritage hotel in Mysuru has 5 rooms: two Standard (₹1,800 a night), two Deluxe (₹3,000) and one Suite (₹5,000). The front desk types short commands all day: book 201 Asha 3 and checkout 201. At closing time, the manager wants a summary of bookings, mistakes, occupancy and revenue per room type.

Pricing rules: a stay of 7 nights or more gets 10% off the room price, and the Suite adds a ₹1,000 service charge to every booking. Build it with classes so that each kind of room knows its own price: that is polymorphism.

What you will practise

  • Design several classes that work together
  • Use inheritance and override a method for a special case
  • Raise clear errors for invalid actions and handle them at the desk
  • Keep state (who is in which room) inside an object

You may use: everything from Parts 1-5, class, inheritance, super(), polymorphism and magic methods, raise, try / except.
Do not use yet: NumPy (Part 7).

Your tasks

  1. Write class Room with number, kind, rate and guest (None when empty), and a method price(nights): rate × nights, with 10% off for 7 nights or more.
  2. Write class Suite(Room) that overrides price(nights): super().price(nights) plus ₹1,000.
  3. Write class Hotel that builds its rooms from the starter's ROOMS list (use Suite for the suite) and has book(number, guest, nights) and checkout(number). They raise ValueError with these messages: Room 999 does not exist, Nights must be at least 1, Room 201 is occupied, Room 201 is empty.
  4. book returns the price; checkout returns the guest's name. The hotel also keeps the number of bookings and the revenue per room kind.
  5. Read commands until done: book <room> <guest> <nights> and checkout <room>. Print Booked 201 (Deluxe) for Asha, 3 nights: ₹9,000.00 (1 night for one) or Checked out 201 (Asha).
  6. For any problem print Error: <message> and count it. Extra messages: Error: Room and nights must be numbers and Error: Unknown command (also for a wrong number of words). The checks go in this order: room exists, nights, occupied.
  7. At done, print Bookings, Errors, Occupied: <n> of 5 rooms (<percent>%), Revenue, and one line per kind: Standard revenue, Deluxe revenue, Suite revenue.

Lines your output must contain

Booked <room> (<Kind>) for <guest>, <n> nights: ₹<amount>
Checked out <room> (<guest>)
Error: <message>
Bookings: <count>
Errors: <count>
Occupied: <n> of 5 rooms (<percent>%)
Revenue: ₹<amount>
Standard revenue: ₹<amount>
Deluxe revenue: ₹<amount>
Suite revenue: ₹<amount>

Money has ₹, commas and 2 decimals. The occupancy percent has 1 decimal. Guest names are one word as typed. Revenue is counted when a room is booked.

Example run

Edge cases to think about

  • Booking a room that is already occupied, or a room number that does not exist.
  • Checking out of an empty room.
  • 7 nights or more: 10% off. The Suite always adds ₹1,000, also after the discount.
  • 0 nights, a word instead of a number, or a wrong number of words.
  • A room can be booked again after checkout.

Hint 1

Room.price: total = self.rate * nights, then if nights >= 7: total = total * 0.9, return total. Suite.price is one line: return super().price(nights) + 1000.

Hint 2

In Hotel.__init__, build a dictionary self.rooms = {} from ROOMS: self.rooms[number] = Suite(...) if kind == "Suite" else Room(...). Then book looks up self.rooms.get(number) and raises the right ValueError.
