Selecting, filtering and changing data

Ask a table questions. Pick rows and columns by label or position, filter with conditions, add new columns with maths and your own rules, sort, and find the top and bottom values.

In this chapter you will learn

  • Pick data with loc (labels, end included) and iloc (positions, end left out)
  • Filter rows with masks, & | ~, isin(), between() and query()
  • Add columns with maths, apply() (also with axis=1) and np.where()
  • Change only some rows with df.loc[condition, "col"] = value
  • Sort with sort_values() and find values with value_counts(), unique() and idxmax()

loc: pick by labels

Easy tip

To keep the examples short, the cells below do not repeat these lines. Try it copies them in for you, so every example still runs.

df.loc[rows, columns] picks data by labels: the index labels on the left and the column names on top. Read the comma as "and": which rows, and which columns.

Trap!

With loc, a slice like 1:3 includes the end label 3. That is different from Python lists and from iloc, where the end is left out.

iloc: pick by position

df.iloc[rows, columns] picks by position numbers (0, 1, 2 ...), ignoring the labels. It works exactly like slicing a list: the end is not included, and -1 means the last one.

Animated explainer: loc[0:2] vs iloc[0:2]

  1. The same table, two ways to cut it. Here the labels and the positions are both 0 to 4.
  2. emp.loc[0:2] uses labels, and the end label is included: rows 0, 1 and 2. Three rows.
  3. emp.iloc[0:2] uses positions, and the end is left out, like a list: positions 0 and 1. Two rows.
  4. emp.iloc[3:5, [0, 2]]: positions 3 and 4, and the columns at positions 0 and 2 (name and salary).

Predict the output

  1. 3 2
  2. 2 2
  3. 3 3
  4. 2 3
Answer

3 2. loc includes the end label (2, 3, 4). iloc stops before position 4 (2, 3).

Don't mix up: loc vs iloc

Rule of thumb: Know the name? loc. Know the position? iloc.

Filtering rows

A condition on a column gives True or False for every row: a boolean mask, exactly like the NumPy masks of Chapter 21. Put it inside df[...] to keep only the True rows.

Join conditions with & (and), | (or) and ~ (not). Each condition needs its own brackets, because & and | are worked out before > and ==.

Animated explainer: How a filter keeps rows

  1. We want the people with a score above 80.
  2. emp["score"] > 80 checks every row and gives a mask: True, False, True, False, True.
  3. emp[mask] keeps the True rows. Notice the index: 0, 2, 4. Filtering keeps the original labels.
Trap!

Python's and / or do not work here: emp[emp["score"] > 85 and emp["salary"] > 50000] raises a ValueError. Use & and |, with brackets around each condition.

Predict the output

  1. 4
  2. 3
  3. 1
  4. 5
Answer

4. IT gives Asha, Neha and Arjun. Score above 90 adds Priya (Asha is already in). That makes 4.

query(): filters written like a sentence

df.query("...") does the same filtering, written like a sentence. Inside the text you use plain and / or, and quotes around text values. Put @ before a Python variable.

Easy tip

Write a query with double quotes inside single quotes, or the other way round: 'dept == "IT"'. Column names with spaces need backticks: `df.query("Annual Salary > 50000")`.

New columns with maths

Maths on columns works row by row, like NumPy arrays: no loop. Store the result under a new name and you get a new column.

Predict the output

  1. 800
  2. 350
  3. 5
  4. [300, 500]
Answer

800. Row by row: 100 × 3 = 300 and 250 × 2 = 500. Together 800.

apply(): your own rule

When a rule needs if / else, write it as a function and use apply(). On a column, apply(func) calls your function once for every value. A lambda is fine for a short rule; a def is clearer for if / elif / else.

When the rule needs several columns, use df.apply(func, axis=1). Now your function gets one whole row at a time, and you read its values by column name.

Animated explainer: apply() on a column vs apply(axis=1) on rows

  1. emp["score"].apply(grade): your function gets one value at a time. First 91.
  2. Then 74, then 83, and so on. The answers form the new column.
  3. emp.apply(bonus_ok, axis=1): now the function gets a whole row, so it can use row["salary"] and row["score"] together. Asha's salary is 70000 or more, so "No".
Trap!

Pass the function without brackets: apply(grade), not apply(grade()). With brackets, Python calls grade straight away with no value, and you get a TypeError.

np.where and setting values with loc

For a simple yes/no rule, np.where(condition, value_if_true, value_if_false) is shorter and much faster than apply. It works on the whole column at once.

You can also set values with loc: put a condition for the rows and a column name, then = a value. Only the matching rows change. A new column name creates the column.

Sorting with sort_values

sort_values("col") sorts the rows by a column, smallest first. Add ascending=False for largest first. The index labels move with their rows.

Predict the output

  1. ['B', 'C', 'A']
  2. ['A', 'B', 'C']
  3. ['A', 'C', 'B']
  4. [1, 2, 3]
Answer

['B', 'C', 'A']. Sorting by v gives 1 (B), 2 (C), 3 (A); then we take the names.

Easy tip

sort_index() puts the rows back in index order. After a filter or a sort, the index may also have gaps; reset_index(drop=True) numbers the rows 0, 1, 2 ... again.

Counting and finding: value_counts, unique and idxmax

value_counts() counts each value, biggest first. With normalize=True you get shares (0 to 1) instead of counts. unique() lists the different values and nunique() counts them.

idxmax() gives the index label of the largest value, and idxmin() of the smallest. Pass that label to loc to see the whole row.

Trap!

max() gives the biggest value. idxmax() gives where it is (the index label). You need idxmax() to find who has the top salary.

Practice

  1. Print the name and city of the rows with the labels 2 to 4 (both included) of emp.

    Hint

    emp.loc[2:4, ["name", "city"]]: with loc the end label is included.

    Solution

    With iloc you would write iloc[2:5, ...] to get the same three rows.

  2. Print the names of the Sales staff whose score is above 70, as a list.

    Hint

    Two conditions with &, each in brackets; then ["name"].tolist().

    Solution

    Meena, Priya and Kiran qualify; Ravi's 68 is too low.

  3. Add a column tax that is 10% of the salary for salaries above ₹50,000 and 5% otherwise (use np.where). Print name, salary and tax for the first 4 rows.

    Hint

    np.where(emp["salary"] > 50000, emp["salary"] * 0.10, emp["salary"] * 0.05).

    Solution

    np.where can choose between two columns, not only two fixed values.

  4. Write a function level(score) that returns "A" for 90 or more, "B" for 70 or more, and "C" otherwise. Add it as a column with apply and print the value counts of the new column.

    Hint

    emp["level"] = emp["score"].apply(level), then value_counts().

    Solution

    The order of the if checks matters: test the highest band first.

  5. Print the name of the person with the lowest salary, using idxmin() and loc.

    Hint

    emp.loc[emp["salary"].idxmin(), "name"].

    Solution

    idxmin() gives the label (3), and loc turns it into the name.

Practice with real data: a year of sales

sales_data.csv has 500 orders from 2024: the date, category, region, sales and profit in rupees, quantity, the customer's age and a satisfaction score from 1 to 5.

  1. How many orders lost money (Profit below 0)? Print the count, and the share of all orders as a percent with 1 decimal.

    Hint

    loss = sales[sales["Profit"] < 0], then len(loss) and len(loss) / len(sales) * 100.

    Solution

    A filter plus len() answers "how many" questions.

  2. Add a column margin = Profit ÷ Sales × 100, rounded to 1 decimal. Print the Category, Sales, Profit and margin of the 3 orders with the highest margin.

    Hint

    Make the column, then sort_values("margin", ascending=False).head(3).

    Solution

    Clothing has the best margins: the cheap items earn the most per rupee.

  3. What share of orders comes from each region? Print value_counts(normalize=True) rounded to 2 decimals.

    Hint

    sales["Region"].value_counts(normalize=True).round(2).

    Solution

    The shares add up to 1. South has the most orders.

  4. Using query(), print how many Electronics orders in the South had a satisfaction score of 4.5 or more.

    Hint

    sales.query('Category == "Electronics" and Region == "South" and Satisfaction_Score >= 4.5').

    Solution

    Three conditions in one readable line.

  5. Print the date, category and sales of the single biggest order, using idxmax().

    Hint

    sales.loc[sales["Sales"].idxmax(), ["Date", "Category", "Sales"]].

    Solution

    A November Electronics order: the Diwali season brings the biggest bills.

Key takeaways

  • loc picks by labels and includes the end of a slice; iloc picks by positions and leaves the end out.
  • Filter with df[mask]; join conditions with &, |, ~ and brackets, or write df.query("...").
  • New columns: maths on columns, np.where() for yes/no rules, apply() for your own function (axis=1 for whole rows).
  • df.loc[condition, "col"] = value changes only the matching rows.
  • sort_values(), value_counts(normalize=True), unique(), nunique(), and idxmax() + loc to find the top row.

  10. Why use np.where() instead of apply() for a yes/no rule?

    It works on the whole column at once, so it is much faster. np.where is vectorised, like the NumPy maths in Part 7.
