Cleaning data with Pandas

Turn a messy file into a clean table. Remove repeats, fill or drop gaps, drop what you do not need, fix types, tidy text with .str, translate values with a dictionary, and turn text into real dates.

In this chapter you will learn

  • Remove repeated rows with drop_duplicates() and gaps with dropna()
  • Fill gaps with fillna() (mean, median, mode) and with ffill() / bfill()
  • Remove columns and rows with drop(), also by a condition
  • Fix types with astype() and tidy text with the .str tools
  • Use map() and replace() with a dictionary, and turn text into dates with pd.to_datetime() and .dt

The cleaning checklist

Real files are messy. In employees.csv you saw extra spaces, mixed capitals, missing salaries, a repeated row and three date styles. Data cleaning means fixing all of that before you analyse, because a wrong value gives a wrong answer.

Diagram: The same six steps work on almost every file. Look first, fix, then look again.

Trap!

Without .copy(), df = raw gives the same table two names, so changing one changes the other. raw.copy() makes a separate table.

Remember this

Most cleaning methods return a new result and leave the table alone. Store the result: df = df.dropna() or df["name"] = df["name"].str.strip(). Older code uses inplace=True; you will see it, but storing the result is clearer.

Removing duplicate rows

drop_duplicates() removes every row that is an exact copy of an earlier one. With subset= it compares only the columns you name, like an ID.

Predict the output

  1. 3
  2. 6
  3. 2
  4. 4
Answer

3. Only one copy of each id stays: 7, 8 and 9.

Missing values: dropna and fillna

You have two choices for a gap: remove the row with dropna(), or fill the gap with fillna(). Dropping is simple but loses data. Filling keeps the row, so choose a sensible value.

Fill withCodeGood for
A fixed valuedf["city"].fillna("Unknown")Text where "unknown" is honest
The mean (average)s.fillna(s.mean())Numbers without extreme values
The medians.fillna(s.median())Numbers with a few very big or small values
The mode (most common)s.fillna(s.mode()[0])Categories, like a department
Trap!

mode() returns a Series, because there can be a tie for most common. Take the first one with [0]. Writing fillna(s.mode()) without [0] fills by matching index labels instead, which is not what you want.

Easy tip

fillna(0) is only right when a gap really means zero, like "no sales that day". A missing salary is not ₹0: filling it with 0 drags the average down.

Filling from neighbours: ffill and bfill

In readings taken over time, the best guess for a gap is often the value next to it. ffill() (forward fill) copies the last known value down. bfill() (backward fill) copies the next known value up.

Animated explainer: ffill copies the last value down; bfill copies the next value up

  1. Five daily temperature readings. Tuesday, Wednesday and Friday are missing.
  2. ffill(): each gap takes the last value above it. Tue and Wed get Monday's 31, Fri gets Thursday's 29.
  3. bfill(): each gap takes the next value below it. Friday stays empty, because nothing comes after it.

Predict the output

  1. [nan, 5.0, 5.0, 9.0]
  2. [5.0, 5.0, 5.0, 9.0]
  3. [nan, 5.0, 9.0, 9.0]
  4. [0.0, 5.0, 5.0, 9.0]
Answer

[nan, 5.0, 5.0, 9.0]. The first value has nothing above it, so it stays nan. The third copies the 5 above it.

Removing rows and columns: drop

drop() removes columns or rows by name. Use columns= for columns and index= for row labels. (Older code writes axis=1 for columns and axis=0 for rows.)

To drop the rows that match a condition, first make the condition. df["score"] < 55 gives True or False for every row, just like a NumPy boolean mask in Chapter 21. df[mask] keeps the True rows, and .index gives their labels, which drop() removes.

Trap!

Without errors="ignore", dropping a column that does not exist stops with a KeyError. That often happens when you run a notebook cell twice: the second time, the column is already gone.

Fixing types: astype

Every column has one type. Numbers saved with symbols, like "₹1,200", are text (object), so you cannot add them. Remove the symbols, then convert with astype().

Easy tip

You will often see astype(int). It works, but the size of a plain int depends on the computer (this browser makes it int32). astype("int64") gives the same result everywhere.

Trap!

astype("int64") fails with a ValueError if the column still has NaN, because a whole-number column cannot hold a gap. Fill or drop the gaps first.

Text columns: the .str tools

Add .str to a text column and you can use string methods on every row at once: no loop needed. These are the same methods you learned in Chapter 8.

Easy tip

regex=False means "replace exactly this text". Without it, some symbols like . or $ would have special meanings. Set it whenever you replace plain text.

In r"@(.+)", @ means the @ sign, .+ means "one or more characters", and the round brackets say which part to keep. So it keeps everything after the @. na=False treats a missing email as "does not contain it".

Predict the output

  2. [' Pune', 'Goa ']
  3. ['pune', 'goa']
  4. ['PUNE', 'GOA']
Answer

['Pune', 'Goa']. strip() removes the spaces at both ends, then title() gives each word a capital first letter.

Map and replace with a dictionary

To change whole values, give a dictionary of old: new. replace() changes the values it finds and keeps the rest. map() looks every value up in the dictionary, and a value that is not there becomes NaN.

Don't mix up: replace() vs map()

replace({...})map({...})
A value in the dictionaryChangedChanged
A value not in the dictionaryKept as it isBecomes NaN
Use it forFixing a few spellingsTranslating every value (codes, short names)

Rule of thumb: Fixing some values? replace(). Turning every value into another? map(), with every value in the dictionary.

Predict the output

  1. [True, False, nan]
  2. [True, False, 'Maybe']
  3. [True, False]
  4. A KeyError
Answer

[True, False, nan]. map() gives NaN for any value that is not in the dictionary, here "Maybe".

Dates: pd.to_datetime

Dates read from a file are text, so you cannot sort them properly or count days. pd.to_datetime() turns them into real dates, with the type datetime64[ns].

Real files mix styles: 2020-08-10, 11/08/2017, 21-Nov-2022. Three options handle that. format="mixed" reads each value in its own style. dayfirst=True reads 11/08/2017 as 11 August (the Indian way), not November 8. errors="coerce" turns anything that is not a date, like "not known", into NaT ("not a time"), instead of stopping with an error.

Trap!

Without dayfirst=True, 03/04/2024 means March 4 (the American way). In India it usually means 3 April. Check a few dates after converting.

Date parts with .dt

Once a column holds real dates, .dt gives you its parts, the same way .str gives you text tools.

Subtract two dates and you get a Timedelta, a length of time. .dt.days gives it in days. Use a fixed "today" so your results stay the same; in real work you would use pd.Timestamp.now(). The days show decimals (2274.0) because two join dates are missing: a number column with a gap is always decimal.

    map() is right here because every value gets translated.

    Solution

    replace() is right here: the other values (< 5, > 10) stay as they are. map() would have turned them into NaN.

Key takeaways

  • Clean a copy (raw.copy()) and store every result: most methods return a new table.
  • drop_duplicates() removes repeats; dropna() removes gaps; fillna() fills them with a value, the mean, the median or mode()[0]; ffill()/bfill() copy a neighbour.
  • drop(columns=[...]) and drop(index=[...]) remove by name; errors="ignore" skips names that are not there.
  • Add .str for text tools on every row; replace({...}) keeps unknown values, map({...}) makes them NaN.
  • pd.to_datetime(col, format="mixed", dayfirst=True, errors="coerce") reads messy dates; .dt gives the year, month, weekday and more.

    So the original stays safe while you change df. df = raw would just give the same table a second name.

    3. [80.0, nan, 60.0]
    4. [80.0, 60.0]

    [80.0, 70.0, 60.0]. The mean of 80 and 60 is 70, and it fills the gap.

    3. It sorts the dates
    4. It removes the time

    It reads 03/04/2024 as 3 April, not March 4. Day first is the Indian (and British) way of writing dates.
