Part 3 · Collections · Overview

Part 3 overview: strings, lists, tuples, sets and dictionaries

The five collections side by side: what each one is, when to use it, and the methods people confuse. Start with the big table, then work through the "don't mix these up" pairs.

The whole Part in 5 lines

  1. Python has five main built-in collections: string (text), list, tuple, set and dictionary.
  2. Strings, lists and tuples are ordered and use index numbers from 0. Sets have no order. Dictionaries look values up by key.
  3. Lists, sets and dicts are mutable (you can change them). Strings and tuples are immutable. String methods like upper() give you a new string instead of changing the old one.
  4. Sets keep only unique items, and dict keys are unique too. Lists, tuples and strings allow duplicates.
  5. Comprehensions build a new list, set or dict in one line: [x * 2 for x in nums if x > 0].

Key definitions

Collection

One variable that holds many values. Python's built-in ones are str, list, tuple, set and dict.

String

An ordered, immutable sequence of characters. In other words: text.

List

An ordered, mutable collection of any values. Duplicates are allowed.

Tuple

An ordered, immutable collection. Think of it as a fixed record whose values belong together.

Set

An unordered collection of unique items. Duplicates disappear automatically.

Dictionary

A collection of key: value pairs. You look values up by their key, and keys are unique.

Sequence

An ordered collection you can index and slice: strings, lists, tuples and range().

Index

An item's position. It starts at 0. Negative indexes count from the end, so -1 is the last item.

Slice

A piece cut out with [start:stop:step]. Start is included, stop is not.

Mutable

Can be changed in place after it is created: lists, sets and dicts.

Immutable

Cannot be changed. Methods hand back a new value, so store the result.

Hashable

A value that can be a dict key or a set item. In practice: immutable values like int, str and tuple.

Method

A function that belongs to a value. Call it with a dot: value.method().

Unpacking

Spreading the items of a collection into separate names. * collects the extras into a list.

Aliasing

b = a does not copy. Both names point at the same list, so a change shows up in both.

Comprehension

A loop that builds a new collection in one line: [expression for item in items if condition].

Rule of thumb: a list, a tuple and a dictionary value accept anything. A set and a dictionary key accept only things that can never change.

Why it works this way

Why can't a set hold a list? A set (and the keys of a dictionary) files every item by its value, like a hotel giving each guest a fixed room based on their name, so it can find them instantly. A list can change after it goes in (you can append to it), and then Python would look in the wrong room and lose it. So only things that can never change are allowed in: strings, numbers, tuples and frozensets. Python calls them hashable. A tuple counts only if everything inside it can never change either.

Try it yourself

Each task needs more than one collection, just like real data work. Every comparison table above also has an Edit and run this example button.

  1. raw = " Asha, RAVI ,neha,Asha ". Clean it into a sorted list of unique, title-case names and print ['Asha', 'Neha', 'Ravi'].

    Hint

    split(","), then strip() and title() each name, put them in a set to drop the duplicate, then sorted().

    Solution

    String methods clean each piece, a set comprehension drops the duplicate, and sorted() gives a list back in a fixed order.

  2. Count how often each fruit appears in fruits = ["apple", "mango", "apple", "kiwi", "apple", "mango"] and print {'apple': 3, 'mango': 2, 'kiwi': 1}.

    Hint

    Start with an empty dict and use counts[f] = counts.get(f, 0) + 1.

    Solution

    get(f, 0) gives 0 the first time a fruit appears, so there is no KeyError.

  3. students = [("Asha", 82), ("Ravi", 67), ("Neha", 91)] is a list of tuples. Print the top student as Neha 91.

    Hint

    Start with best = students[0]. Loop over the list and keep the tuple with the higher mark (s[1] > best[1]). Then unpack best into two names.

    Solution

    Each record is a tuple because it is fixed. The list holds the records, and s[1] reads the mark from each one. (In Part 4 you will learn a shortcut: max(students, key=lambda s: s[1]).)

  4. a = {"Asha", "Ravi", "Neha"} joined the morning class and b = {"Ravi", "Kiran"} the evening class. Print who came to both and who came only in the morning, each as a sorted list.

    Hint

    & gives the people in both sets, - gives the people only in the first.

    Solution

    Set operations compare whole groups in one step. sorted() turns the result into a list with a fixed order.

Flashcards

String vs tuple: definition
A string is an ordered, immutable sequence of characters (text). A tuple is an ordered, immutable sequence of any values (a fixed record).
String vs tuple: use cases
String: names, emails, messages, cleaning text. Tuple: coordinates, dates, returning several values, dictionary keys.
Which collections are mutable?
List, set and dictionary. String and tuple are immutable.
Which collections keep order and have an index?
String, list and tuple. A dict keeps insertion order but you look up by key. A set has no order.
Which collections allow duplicates?
String, list and tuple. A set never does. A dict allows duplicate values but not duplicate keys.
How do you write an empty set?
set(). Writing {} makes an empty dictionary.
How do you write a one-item tuple?
With a trailing comma: (5,). Without it, (5) is just the number 5.
append() vs extend()
append(x) adds x as one item. extend(items) adds each item separately.
sort() vs sorted()
lst.sort() changes the list and returns None. sorted(x) returns a new list and works on any collection.
d[key] vs d.get(key, default)
d[key] raises KeyError if the key is missing. get returns None or your default instead.
remove() vs discard() on a set
remove raises KeyError if the item is missing. discard does nothing.
find() vs index() on a string
find returns -1 when missing. index raises ValueError.
How do you copy a list safely?
b = a.copy(), a[:] or list(a). b = a only makes a second name.
Where does the if go in a comprehension?
Filter: at the end, [x for x in items if cond]. Transform: at the front with else, [a if cond else b for x in items].
Which collection for which job?
Look up by name: dict. Unique items: set. Fixed values: tuple. Text: string. Everything else: list.
