Errors and exceptions

Errors are not failures, they are messages. Learn to read them in seconds, and use try/except so bad input does not crash your program.

In this chapter you will learn

  • Tell syntax errors from runtime exceptions
  • Read a traceback from the bottom up
  • Recognise the 10 most common exceptions and their usual fix
  • Handle errors with try, except, else and finally
  • Raise your own errors with raise

Watch it explained

  • English: Python Tutorial: Using Try/Except Blocks for Error Handling by Corey Schafer (about 11 min)

Two kinds of errors

Syntax errors

  • Grammar mistakes: missing colon, bracket or quote
  • Found before anything runs
  • Nothing in the cell runs at all
  • Fix: correct the code

Exceptions (runtime errors)

  • The grammar is fine, but something goes wrong while running
  • Lines before the error do run
  • Can be caught with try/except
  • Fix: handle it, or fix the data or logic

Reading a traceback

When an exception is not handled, Python prints a traceback: the trail of function calls that led to the error. It looks scary but follows a fixed shape.

try and except

Put risky code inside try:. If an exception happens, Python jumps straight to the matching except: block instead of crashing. The rest of the program carries on.

Animated explainer: What happens when an error hits a try block

  1. Python enters the try block. From here on, errors will be caught.
  2. int("five") fails. Python raises a ValueError.
  3. Python skips the rest of the try block (line 3 never runs) and looks for an except that matches ValueError. This one does.
  4. The except block runs instead of a crash.
  5. Then the program simply carries on. Without try/except, it would have stopped at line 2.
Easy tip

Catch several types in one line with a tuple: except (ValueError, TypeError):.

else and finally

BlockRuns when
try:Always, first
except:Only if a matching error happened in try
else:Only if no error happened in try
finally:Always, error or not. Used for clean-up like closing files

Diagram: If a matching error happens, except runs. If no error happens, else runs. finally always runs.

Trap!

Notice finally printed "Done trying" before the returned value was printed, even though return came first. finally runs on the way out of the function, no matter what.

raise: create your own errors

Sometimes the data is wrong even though Python has no problem with it, like a negative age. Use raise to stop with a clear message.

Real uses

Why analysts care

Real files always contain some junk: "N/A", blanks, "1,200" with a comma. try/except lets your script skip or log the bad rows instead of dying on row 40,000 of 50,000.

Trap! The bare except

except: with nothing after it catches every error, including typos in your own code. Your bug is silently hidden. Always name the error you expect, like except ValueError:.

assert checks that something is True. If it is False, Python stops with AssertionError and your message.

Key takeaways

  • Syntax errors stop the code before it runs. Exceptions happen while running.
  • Read a traceback from the bottom: the last line is the type and message, the arrows show the line.
  • try: risky code, except SomeError: what to do instead. Name the error you expect.
  • else runs when there was no error. finally always runs.
  • raise ValueError("message") stops with your own clear error.

Flashcards

Syntax error vs exception
Syntax error: bad grammar, found before running, nothing runs. Exception: happens while running and can be caught with try/except.
How do you read a traceback?
From the bottom: last line = error type and message. In Jupyter, the ----> arrows show the failing line. Read upward for who called it.
TypeError vs ValueError
TypeError: wrong type ("a" + 1). ValueError: right type, bad value (int("abc")).
IndexError vs KeyError
IndexError: list position past the end. KeyError: dictionary key missing.
try/except syntax
What do else and finally do in a try?
else: runs if no error. finally: always runs, used for clean-up.
How do you get the error message?
except ValueError as e: then print(e).
How do you raise your own error?
raise ValueError("Age cannot be negative")
Why avoid a bare except:?
It catches everything, including your own bugs, and hides them.
