# Python Study Hub: build notes

Everything needed to rebuild and extend the site at https://puttasrinathraju.github.io/python-study-hub/.
The published site is the repo root. This `source/` folder holds the build files.

## Layout
- `source/hub2/`: the site source (single-page app built from JS data files).
  - `parts.js` (PARTS, `chapter()`, `overview()`), `ch/NN_id.js` (one chapter each), `decks.js`, `realdata.js`, `mixed.js` (Part 3 "collections inside collections"; generated by `gen/gen_mixed.py`), `posters_*.js`, `ov_N.js` (Part overviews), `sheets.js`, `videos.js`, `reference.js` (generated by `genref.py`), `exercises.js` (generated by `gen/gen_ex.py`), `bigtests.js` (generated by `gen/gen_bigtests.py`), `projects.js` (generated by `gen/gen_projects.py`), `engine.js` (all UI), `base.html` (CSS + shell), `py-worker.js` (Pyodide 0.27.7 runner in a Web Worker), `hubcharts.py` (chart support, see below), `sw.js` (offline cache, VERSION `pyhub-v7`).
  - `data/`: practice files the browser runner writes into Python's folder the first time code mentions them (`hotel_bookings.csv`, `employees.csv`, `employees.xlsx`, `sales_data.csv`, `student_scores.csv`, `tips.csv`). Parts 8-10 files are made by `gen/gen_data.py` (fixed seed; same columns as the course files). `tips.csv` is Seaborn's dataset (github.com/mwaskom/seaborn-data); the runner also copies it to Seaborn's data folder, so `sns.load_dataset("tips")` works offline.
  - `py/`: pure-Python wheels the runner loads by URL: `seaborn-0.13.2`, `openpyxl-3.1.5` + `et_xmlfile-2.0.0` (for `pd.read_excel`). Seaborn and openpyxl are not in Pyodide.
  - `build_site.py`: runs `node static_pages.js` (text pages in `learn/`, sitemap, no-JS fallback) then writes `site/` (copies `data/*.csv|xlsx`, `py/*.whl`, `img/*.webp` and `img/sheet-*.jpg`, and puts `hubcharts.py` into `site/py-worker.js` in place of `/*@@HUBCHARTS@@*/""`).
  - `extract.js` + `runcheck.py`: pull every runnable example/answer into `out/items.json` and run it in real Python. Must report `failed 0`.
  - `pyodide_check.js <prefix...>`: runs items in the browser's Python (needs the local test server). It is the final judge.
- `source/gen/`: generators. `bt/bt_NN_<chapterid>.py` = one Big Test each (see `bt_08_strings.py`). `pj/pj_partN.py` = the 3 projects of Part N (see `pj_part1.py`), `pj_analyse.py` = the code analyser used for scoring (runs in browser Python).
  - Parts 8-10: `chlib.py` (shared helpers: runs every example in the matching Python, chart pictures and summaries, chart checks, JS writer), `gen_pandas1..4.py` (chapters 23-26; each also writes its revision poster into the chapter file), `gen_ov8.py` (Part 8 overview + `SHEETS[8]` between `/* @@SHEET8 */` markers in `sheets.js`), `gen_sheetimgs.py N` (the sheet pictures `img/ovN-*.webp`, drawn with Matplotlib), `ex_new.py` (quick exercises of Parts 8-10, blanks marked `@@`), `ref_pandas.py` / `ref_mpl.py` (Pandas and Matplotlib rows of the reference page, used by `genref.py`), `gen_data.py` (practice data). Part 9: `gen_mpl1.py`, `gen_mpl2.py` (chapters 27-28), `gen_ov9.py` (overview + `SHEETS[9]`). The picture sheet JPG: `node sheetshot.js N 1800 img` (server running), then turn `img/sheet-ovN.png` into `img/sheet-ovN.jpg` (PIL, quality 85) and delete the PNG.
- `source/merge_extra/`: `404.html` and the `v2/` forwarding stub. Copy these to the repo root on every deploy (never delete them).
- `img/` is NOT in source: copy the repo root `img/` folder into `hub2/img/` before building (generated pictures are written to `hub2/img/`; copy new ones back to the repo root when publishing).

The browser runs Pyodide 0.27.7: Python 3.12, pandas 2.2.3, numpy 2.0.2, matplotlib 3.8.4, scipy 1.14.1 (+ seaborn 0.13.2 from `py/`). Run every generator and `runcheck.py` with the same versions:

```bash
  python-dateutil==2.9.0.post0 pytz==2024.1 tzdata==2024.1 six==1.16.0 contourpy==1.3.0 cycler==0.12.1 fonttools==4.51.0 \

```
`chlib.py` refuses to run with another pandas. Checks run with `COLUMNS=80 LINES=24` (the worker sets the same), `MPLBACKEND=Agg` and `SEABORN_DATA` pointing at the data folder.

## Build, check, test, publish
```bash
PY=~/venv/bin/python
cd source/gen && $PY gen_pandas1.py   # ... each changed chapter generator, gen_ov8.py, gen_ex.py
$PY gen_bigtests.py && $PY gen_projects.py   # writes bigtests.js, projects.js, out/pj_items.json, out/pj_weak.json
cd .. && COLUMNS=80 $PY genref.py            # reference.js
cd hub2 && node extract.js && $PY runcheck.py      # must say failed 0
python3 build_site.py                                # writes site/
# local test (Playwright + Chromium are preinstalled)
mkdir -p ../site_test && cp -r site/. ../site_test/ && cp -r ../merge_extra/. ../site_test/ && cp out/items.json ../site_test/
# pyodide_local: npm pack pyodide@0.27.7, extract package/* into site_test/pyodide_local/, plus the wheels the course needs and their
# pyodide-lock.json entries (already in the npm package): stream github.com/pyodide/pyodide/releases/download/0.27.7/pyodide-0.27.7.tar.bz2 | tar -xj
# --wildcards for numpy, pandas, matplotlib, matplotlib_pyodide, contourpy, cycler, fonttools, kiwisolver, packaging, pillow, pyparsing,
# python_dateutil, pytz, six, tzdata, scipy, openblas, micropip.
cd ../site_test && python3 -m http.server 8765      # run in background; open http://localhost:8765/?localpy#<route>
node pyodide_check.js pandas1 bt:pandas pj:p8 ...    # from hub2: every new item must pass in browser Python
# publish: copy site/ + merge_extra/ to the repo root, sync source/, commit, push to main (GitHub Pages serves main)
```
Test suites (need the server): `node v6test.js`, `node bttest.js`, `node pjtest.js`, `node parttest.js <part>`. Console errors `ERR_TUNNEL_CONNECTION_FAILED` are only the sandbox blocking YouTube/fonts.

Browser Python is 32-bit (NumPy ints are int32). Never print dtypes/itemsize, huge int sums, or exact random values in checked answers. Never print a set of strings directly (order changes per run): use `sorted()`.
Pandas traps found while checking Parts 8-10 (laptop and browser differ):
- `value_counts()` and single-column `sort_values()` order **ties** differently: use data without ties, or sort by two columns.
- `df.info()` prints memory sizes that differ: use `df.info(memory_usage=False)` as the last line of a cell.
- `astype(int)` and NumPy-made int columns are int32 in the browser: use `astype("int64")`; never print the dtype of `np.where(..., 1, 0)`.
- Lists of NumPy numbers print as `np.int64(5)`: print plain values or `.tolist()`.
- Any warning (FutureWarning about `observed=`, setting floats into int columns, Seaborn palette without hue) goes into the learner's output: generators fail on stderr, so fix the code instead.

## Charts in the browser (Parts 9-10, ready since Part 8)
- `hubcharts.py` is imported by the worker before any code that mentions matplotlib/seaborn: Agg backend, `plt.show()` = keep a PNG + facts of every open figure and close it, and wrappers on Axes plotting methods (plot, bar, barh, hist, scatter, pie, boxplot/bxp, imshow, pcolormesh, violinplot, fill_between, ...) and on Seaborn functions record what was drawn. After the run the worker sends `figs` (PNG + facts per figure: axes, kinds, bars, lines, points, wedges, boxes, images, meshes, title, labels, legend, tick labels, bar heights, texts, grid, spines, suptitle, colorbars).
- A practice task, Big Test `W`/`F` question or exercise may carry `chart` (a spec, e.g. `{"kind": "bar", "bars": 5, "title": True, "xlabel": True}`; keys: kind, bars, lines, points, wedges, boxes, violins, images, meshes, title, xlabel, ylabel (True or exact text), legend (True or list), xticks, yticks, heights, texts, text_has, grid, spines, axes, figs, suptitle, colorbar, sns, ax (one spec per axes)). The worker runs `hubcharts.check(spec)` and returns clear problems ("The y-axis label is missing", "Expected 5 bars, found 4"). The page shows what is checked and the learner's chart under the output.
- Generators run chart code through `chlib.chart_run` (the same file): pictures go to `img/<prefix>-NN.webp` (shown under the example as `img`), and `sum` (a text summary) lets `runcheck.py`/`pyodide_check.js` compare laptop and browser charts.
- Projects with charts (`charts=True` on a test): `post` prints `--- charts ---` and the chart report (`_hubcharts.project_report()`: `Figures: N`, `Figure 1: 4 charts, title: ...`, `Chart 1.2: barh, 4 bars, title: ..., x: ..., y: ...`; chart kinds sorted A to Z, so drawing order does not matter). On the page `post` is its own run after the learner's program, so the report reads `LAST` (the charts of the run before); the build checks run everything in one go and use `project_report(this_run=True)` (see `full()` in `gen_projects.py`). `expect()` returns `(printed_lines, chart_lines)`; a test that draws nothing expects `Figures: 0`.

## Content rules (from the owner, Srinath)
- Plain, simple English. Short sentences. Indian context is fine (₹, Indian names and cities).
- Quality is 100% important. Save tokens wherever possible, but never at the cost of quality.
- Every code example/answer must be run in real Python (generators do this) and in browser Python.
- A chapter's test/project may only use concepts from that chapter and earlier chapters. Never use a later concept. No repeated questions.
- Laptop-only code (MySQL, web APIs) is shown with `nr: 1` and a "Laptop only" title; everything else runs on the site.
- A code block's `pre` runs first but is not shown (the chapter's shared table, shown once at the top with a tip); Try it and the checks include it.

## Big Tests (route `#test-<chapterid>`, shown as "N.1 Big Test")
- 25 questions: 15 write code (`W`), 5 fix the code (`F`), 5 type the output (`T`) (the generator checks the mix). Levels: 8 Basic, 10 Medium, 7 Challenge (challenge = combine skills of the same chapter, never new concepts).
- `sec` must be an exact heading of that chapter (the generator checks). No `input()` in Big Test answers.
- Done: every chapter 1-28 (1.1 to 28.1; the projects chapter gets no Big Test). NumPy tests never print dtypes or exact random values. Big Tests can read the practice data files (the generator uses `chlib.WORK`). Chart questions carry `chart` and get `img`/`sum`.
- The last attempt's weak sections are saved in `store` key `bt` (`{best, last, weak}`) and shown on My Projects.

## Projects (routes `#projects-N`, `#project-pN-K`, `#myprojects`)
- 3 per Part (Beginner, Intermediate, Challenging), data-analyst themes, everything on the site. Done: Part 1 (p1-1 Daily sales summary, p1-2 Monthly KPI report, p1-3 Website session analytics), Part 2 (p2-1 Daily bills summary, p2-2 Class marks and grades, p2-3 Loan repayment schedule; no lists, because lists are taught in Part 3), Part 3 (p3-1 Clean a customer list, p3-2 Sales by region, p3-3 Customer feedback analysis), Part 4 (p4-1 GST invoice builder, p4-2 Monthly payroll, p4-3 Stock price tracker; `need` can require named functions with `def:<name>`), Part 5 (p5-1 Clean a sales file, p5-2 Hotel bookings report, p5-3 Monthly budget report), Part 6 (p6-1 Stock inventory with a class, p6-2 Bank accounts with rules, p6-3 Hotel booking desk), Part 7 (p7-1 Weekly sales with NumPy, p7-2 Store sales matrix, p7-3 Discount what-if planner), Part 8 (p8-1 Clean an HR staff file, p8-2 Monthly sales report, p8-3 Student results analysis; every test gives its own CSV files, and `expect()` recomputes the answer with the csv module), Part 9 (p9-1 Monthly sales chart, p9-2 Sales overview: two charts, p9-3 Sales dashboard; the chart report is checked too).
- The runner imports NumPy / Pandas / the chart libraries once before each timed test run, so loading never counts towards the 10-second limit. `safe()` in the pj files keeps expected money values and percents away from exact rounding edges.
- File tests (Part 5+): a test may have `files` (name -> text, written before the run), `remove` (names deleted first), `data: True` (needs `hotel_bookings.csv`) and `outfile` (a file the program must write; `expect()` then returns `(printed_lines, file_lines)`). The generator stores the exact `setup` and `post` Python in each test; the browser runs setup, then the learner's program (timed), then post (prints `--- <outfile> ---` and the file). A project's `sample` files are shown in the brief with a button that creates them in the runner.
- Each project in `pj_partN.py`: brief (story, objectives, may/mustnot, 5-10 tasks, `lines` the output must contain + `rules`, edge cases), 3 hints, starter, `sol` (model answer), `weak` (a typical weaker attempt, only for testing), `need` (features the analyser must find), `expect(inputs)` (an independent formula for the expected lines) and 9 tests (3 `main`, 3 `logic`, 3 `edge`; `check` = which line prefixes a test looks at; `tip` = feedback when it fails).
- `gen_projects.py` runs the model answer for every test with the inputs echoed exactly like the browser runner, asserts every expected line appears as a whole line, checks the starter passes nothing and the weak answer passes fewer tests, and checks the model answer uses every `need` feature, nothing from a later Part (`FEATURES` table; imports are features too: `import:numpy` Part 7, `import:pandas` 8, `import:matplotlib` 9, `import:seaborn` 10) and passes every readability check. For Part 2+ add that Part's taught built-ins to `BUILTINS`. `df`, `ax`, `x` and `y` count as clear names (`SHORT_OK` in `pj_analyse.py`).
- Score /100 (engine.js `pjShow`): correctness 30 (main tests), logic 20, edge 10, use of concepts 25 (share of `need` found by `pj_analyse.py` in browser Python, minus 5 per later-Part feature), readability 15 (names of stored variables >= 3 letters 5 (loop and comprehension variables are not checked), own comment or docstring if > 8 code lines 4, lines <= 100 chars 2, 4-space indents/no tabs 2, spaces around `=` 2). 10-second timeout per test (uses `pyStop`). 70+ = "Ready for the next project". Saved in `store` key `pj` (`{best, last, attempts, hints, parts, todo}`).
- Text page: `learn/projects-partN.html` (model answers folded). Browser tests: `node pjtest.js` (Part 1 plus timeouts and errors) and `node parttest.js <part>` (that Part's Big Tests 25/25, model answers 100, weak answers lower, phone width). Both need the local server.
