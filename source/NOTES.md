# Python Study Hub: build notes

Everything needed to rebuild and extend the site at https://puttasrinathraju.github.io/python-study-hub/.
The published site is the repo root. This `source/` folder holds the build files.

## Layout
- `source/hub2/`: the site source (single-page app built from JS data files).
  - `parts.js` (PARTS, `chapter()`, `overview()`), `ch/NN_id.js` (one chapter each), `decks.js`, `realdata.js`, `mixed.js` (Part 3 "collections inside collections"; generated by `gen/gen_mixed.py`), `posters_*.js`, `ov_N.js` (Part overviews), `sheets.js`, `videos.js`, `reference.js` (generated by `genref.py`), `exercises.js` (generated by `gen/gen_ex.py`), `bigtests.js` (generated by `gen/gen_bigtests.py`), `projects.js` (generated by `gen/gen_projects.py`), `engine.js` (all UI), `base.html` (CSS + shell), `py-worker.js` (Pyodide 0.27.7 runner in a Web Worker), `sw.js` (offline cache, VERSION `pyhub-v7`).
  - `build_site.py`: runs `node static_pages.js` (text pages in `learn/`, sitemap, no-JS fallback) then writes `site/`.
  - `extract.js` + `runcheck.py`: pull every runnable example/answer into `out/items.json` and run it in real Python. Must report `failed 0`.
  - `pyodide_check.js <prefix...>`: runs items in the browser's Python (needs the local test server). Use it for anything NumPy or platform-sensitive.
- `source/gen/`: generators. `bt/bt_NN_<chapterid>.py` = one Big Test each (see `bt_08_strings.py`). `pj/pj_partN.py` = the 3 projects of Part N (see `pj_part1.py`), `pj_analyse.py` = the code analyser used for scoring (runs in browser Python).
- `source/merge_extra/`: `404.html` and the `v2/` forwarding stub. Copy these to the repo root on every deploy (never delete them).
- `img/` is NOT in source: copy the repo root `img/` folder into `hub2/img/` before building.

## Build, check, test, publish
```bash
cd source/gen && python3 gen_bigtests.py && python3 gen_projects.py   # writes bigtests.js, projects.js, out/pj_items.json, out/pj_weak.json
cd ../hub2 && node extract.js && python3 runcheck.py      # must say failed 0
python3 build_site.py                                          # writes site/
# local test (Playwright + Chromium are preinstalled)
mkdir -p ../site_test && cp -r site/. ../site_test/ && cp -r ../merge_extra/. ../site_test/ && cp out/items.json ../site_test/
# pyodide_local: npm pack pyodide@0.27.7, extract package/* into site_test/pyodide_local/,
# plus numpy-2.0.2-cp312-cp312-pyodide_2024_0_wasm32.whl (stream github.com/pyodide/pyodide/releases/download/0.27.7/pyodide-0.27.7.tar.bz2 | tar -xj --wildcards '*/numpy-2.0.2-*.whl')
cd ../site_test && python3 -m http.server 8765      # run in background; open http://localhost:8765/?localpy#<route>
# publish: copy site/ + merge_extra/ to the repo root, commit, push to main (GitHub Pages serves main)
```
Browser Python is 32-bit (NumPy ints are int32). Never print dtypes/itemsize, huge int sums, or exact random values in checked answers. Never print a set of strings directly (order changes per run): use `sorted()`.

## Content rules (from the owner, Srinath)
- Plain, simple English. Short sentences. Indian context is fine (₹, Indian names and cities).
- Quality is 100% important. Save tokens wherever possible, but never at the cost of quality.
- Every code example/answer must be run in real Python (generators do this) and in browser Python.
- A chapter's test/project may only use concepts from that chapter and earlier chapters. Never use a later concept. No repeated questions.

## Chapter order (id: title) and Parts
Part 1: intro, variables, output, operators. Part 2: conditions, forloops, whileloops. Part 3: strings, lists, tuples, sets, dicts, comprehensions.
Part 4: functions, functions2 (args/kwargs, scope, lambda, recursion, iterators, generators, decorators). Part 5: errors, files, modules. Part 6: oop. Part 7: numpy1, numpy2, numpy3. Part 8: projects.
Chapter numbers: 1 intro ... 15 functions2, 16 errors, 17 files, 18 modules, 19 oop, 20 numpy1, 21 numpy2, 22 numpy3, 23 projects.

## Big Tests (route `#test-<chapterid>`, shown as "N.1 Big Test")
- 25 questions: 15 write code (`W`), 5 fix the code (`F`), 5 type the output (`T`). Levels: 8 Basic, 10 Medium, 7 Challenge (challenge = combine skills of the same chapter, never new concepts).
- `sec` must be an exact heading of that chapter (the generator checks). No `input()` in Big Test answers.
- Done: intro (1.1), variables (2.1), output (3.1), operators (4.1), strings (8.1). To do: every other chapter 5-22 except 23 (projects).
- The last attempt's weak sections are saved in `store` key `bt` (`{best, last, weak}`) and shown on My Projects.

## Projects (routes `#projects-N`, `#project-pN-K`, `#myprojects`)
- 3 per Part (Beginner, Intermediate, Challenging), data-analyst themes, everything on the site. Done: Part 1 (p1-1 Daily sales summary, p1-2 Monthly KPI report, p1-3 Website session analytics). To do: Parts 2-7, one `gen/pj/pj_partN.py` each.
- Each project in `pj_partN.py`: brief (story, objectives, may/mustnot, 5-10 tasks, `lines` the output must contain + `rules`, edge cases), 3 hints, starter, `sol` (model answer), `weak` (a typical weaker attempt, only for testing), `need` (features the analyser must find), `expect(inputs)` (an independent formula for the expected lines) and 9 tests (3 `main`, 3 `logic`, 3 `edge`; `check` = which line prefixes a test looks at; `tip` = feedback when it fails).
- `gen_projects.py` runs the model answer for every test with the inputs echoed exactly like the browser runner, asserts every expected line appears as a whole line, checks the starter passes nothing and the weak answer passes fewer tests, and checks the model answer uses every `need` feature, nothing from a later Part (`FEATURES` table) and passes every readability check. For Part 2+ add that Part's taught built-ins to `BUILTINS` (Parts without a list skip the built-in check).
- Score /100 (engine.js `pjShow`): correctness 30 (main tests), logic 20, edge 10, use of concepts 25 (share of `need` found by `pj_analyse.py` in browser Python, minus 5 per later-Part feature), readability 15 (names >= 3 letters 5, own comment if > 8 code lines 4, lines <= 100 chars 2, 4-space indents/no tabs 2, spaces around `=` 2). 10-second timeout per test (uses `pyStop`). 70+ = "Ready for the next project". Saved in `store` key `pj` (`{best, last, attempts, hints, parts, todo}`).
- Text page: `learn/projects-partN.html` (model answers folded). Browser test: `node pjtest.js` (needs the local server; reference answers must score 100, weak answers less).
