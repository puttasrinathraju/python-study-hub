Classes and objects (OOP)

Object-oriented programming bundles data and the functions that work on it into one unit. It is how the PDF's inventory system is built, and how libraries like pandas are designed.

In this chapter you will learn

  • Understand the difference between a class and an object
  • Write __init__ and understand self
  • Add attributes and methods, and know class vs instance attributes
  • Use magic methods like __str__, __len__ and __eq__
  • Apply the four pillars: encapsulation, inheritance, polymorphism, abstraction

Class vs object

A class is a blueprint. An object (also called an instance) is a real thing built from that blueprint. One class can make many objects, each with its own data.

Diagram: One blueprint (dashed), three real objects. Each object has its own values but the same methods.

Think of it like this

You have used objects all along. "hello" is an object of class str, and .upper() is one of its methods. [1, 2] is an object of class list, with methods like .append(). Now you will make your own classes.

__init__ and self

__init__ is a special method that runs automatically whenever you create an object. It sets up the object's starting data. self is the object being created or used. Python passes it in for you.

Animated explainer: What happens when you create two objects

  1. Python reads the class definition and stores the blueprint. No student exists yet.
  2. Student("Asha", 82) creates a new, empty Student object in memory (object 1) and calls __init__ on it.
  3. Inside __init__, self is object 1. name is "Asha" and marks is 82.
  4. self.name = name stores the name on the object. It becomes an attribute of object 1.
  5. Same for marks.
  6. __init__ finishes and s1 now points at object 1.
  7. The same steps run again for Ravi, creating a separate object 2. Each object keeps its own data.
  8. Use a dot to read an attribute: s1.name is "Asha", s2.marks is 67.
self, explained simply

self means "this particular object". When you call s1.grade(), Python actually runs Student.grade(s1), so inside the method, self is s1. It is always the first parameter of a method. You never pass it yourself.

Attributes and methods

Attributes are the object's data (variables attached to it). Methods are functions defined inside the class that work on that data.

Trap! Forgetting self

Every method needs self as its first parameter, and you must write self.marks, not just marks, to reach the object's data. Forgetting self in the def line gives a TypeError like "takes 0 positional arguments but 1 was given".

Class attributes vs instance attributes

An instance attribute (self.name) belongs to one object. A class attribute is written directly in the class and is shared by all objects. It is handy for constants and counters.

Magic methods: __str__ and friends

Magic methods (also called dunder methods, for "double underscore") let your objects work with Python's built-in features. Without __str__, printing an object shows something unhelpful like <__main__.Product object at 0x7f3a...>.

Inheritance: building on another class

Inheritance lets a new class (the child) reuse everything from an existing class (the parent) and add or change parts. Write the parent's name in brackets. super() lets the child call the parent's version of a method.

Diagram: Children get everything from the parent, then add their own parts.

Polymorphism: same method name, different behaviour

Polymorphism means "many forms". Different classes can have a method with the same name, and you can call it on any of them without checking which class it is.

Think of it like this

len() is polymorphic too: len("hello"), len([1, 2]) and len({"a": 1}) all work, even though each type counts differently.

Encapsulation: protecting data

Encapsulation means keeping an object's data safe and only changing it through methods that check the rules. Python marks private attributes by convention: one underscore _balance means "internal, please don't touch". Two underscores (__balance) make Python hide the name.

Class methods and static methods

A @classmethod gets the class (cls) instead of an object, and is often used as an alternative constructor. A @staticmethod gets neither. It is just a function that lives in the class because it belongs there logically. You can also put a class inside another class (an inner class), but you will rarely need to.

Slides: OOP in six slides

  1. A class bundles data and behaviour.

    Data = attributes (self.name). Behaviour = methods (def grade(self)). Objects are built from the class.

  2. Pillar 1: Encapsulation

    Keep data inside the object and change it through methods that check the rules. A bank balance should only change through deposit() and withdraw().

  3. Pillar 2: Inheritance

    A child class reuses a parent class and adds to it. class Student(Person): gets everything a Person has.

  4. Pillar 3: Polymorphism

    Different classes, same method name. shape.area() works for circles and rectangles. Your loop does not care which is which.

  5. Pillar 4: Abstraction

    Hide the complicated details behind simple methods. You call df.groupby() in pandas without knowing the thousands of lines inside it.

  6. You already use OOP every day

    In pandas, df is an object of class DataFrame. df.head(), df.describe() and df.groupby() are its methods, and df.shape is an attribute. Understanding classes makes those libraries feel much less magical.

Key takeaways

  • A class is a blueprint, an object is one thing made from it: s = Student("Asha", 82).
  • __init__ sets up each new object. self is the object itself and is the first parameter of every method.
  • Instance attributes (self.x) belong to one object. Class attributes are shared.
  • __str__ controls print(obj). Other magic methods hook into ==, <, len(), +.
  • Inheritance: class Child(Parent): plus super().__init__(...). Polymorphism: same method name on different classes.
  • Encapsulation: protect data with _name / __name and methods or @property.

Chapter quiz

  1. What is the relationship between a class and an object?

    1. They are the same thing
    2. A class is a blueprint, an object is built from it
    3. An object is a blueprint for classes
    4. Classes are only for numbers
    Answer

    A class is a blueprint, an object is built from it. One class can create many objects (instances).

  2. When does __init__ run?

    1. When you call any method
    2. Automatically, every time a new object is created
    3. Only when you call __init__() yourself
    4. When the program ends
    Answer

    Automatically, every time a new object is created. __init__ is the constructor. It runs on creation.

  3. What is self?

    1. The class name
    2. The object the method is working on
    3. A Python keyword for loops
    4. The parent class
    Answer

    The object the method is working on. self refers to the current object. Python passes it automatically.

  4. What does this print?

    1. Moti says woof
    2. self says woof
    3. Dog says woof
    4. An error
    Answer

    Moti says woof. The object stores name = "Moti" and speak() reads self.name.

  5. Which method controls what print(obj) shows?

    1. __init__
    2. __str__
    3. __len__
    4. __print__
    Answer

    __str__. print() calls str(obj), which uses __str__.

  6. What does class Student(Person): mean?

    1. Student is an object of Person
    2. Student inherits from Person
    3. Person inherits from Student
    4. Student and Person are the same
    Answer

    Student inherits from Person. The class in brackets is the parent.

  7. What does super().__init__(name) do in a child class?

    1. Creates a new parent object
    2. Runs the parent class's __init__ for this object
    3. Deletes the parent
    4. Calls the child's own __init__ again
    Answer

    Runs the parent class's __init__ for this object. It lets the parent set up its part of the object.

  8. Two classes both have an area() method, and a loop calls shape.area() on each. What is this called?

    1. Inheritance
    2. Encapsulation
    3. Polymorphism
    4. Recursion
    Answer

    Polymorphism. Same method name, different behaviour per class.

  9. What does a double underscore like self.__balance do?

    1. Makes it faster
    2. Makes the attribute private (hidden from outside access by that name)
    3. Makes it a class attribute
    4. Nothing at all
    Answer

    Makes the attribute private (hidden from outside access by that name). Python hides it through name mangling, so obj.__balance raises AttributeError.

Flashcards

Class vs object
A class is the blueprint. An object (instance) is one thing built from it.
What is __init__?
The constructor: a method that runs automatically when an object is created, to set up its attributes.
What is self?
The current object. It is the first parameter of every method. s1.grade() runs Student.grade(s1).
Attribute vs method
Attribute: data on the object (self.name). Method: a function in the class (def grade(self):).
Class attribute vs instance attribute
Class attribute: defined in the class body, shared by all objects. Instance attribute: self.x, one per object.
What does __str__ do?
Returns the text that print(obj) shows.
Inheritance syntax
What is method overriding?
A child class defines a method with the same name as the parent's, replacing it.
What is polymorphism?
Different classes with the same method name, so one piece of code can work with all of them.
What is encapsulation?
Keeping data inside the object and changing it only through methods that check the rules. _x means internal, __x is hidden.
What does @property do?
Lets you read a method like an attribute (room.rate), and add a setter that validates new values.
The four pillars of OOP
Encapsulation, inheritance, polymorphism, abstraction.
