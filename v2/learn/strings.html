A string is a sequence of characters in a fixed order. Every character has a position number called an index. len() tells you how many characters there are, including spaces.

Indexing: one character at a time

Diagram: Positive indexes start at 0 on the left. Negative indexes start at -1 on the right.

Remember this

Counting starts at 0, not 1. So the first character is [0] and the last is [len - 1], or simply [-1]. Negative indexes are the easy way to grab things from the end.

Trap! Index out of range

"Python" has 6 characters, indexes 0 to 5. Asking for index 6 is an error.

Slicing: cut out a piece

Slicing uses [start:stop:step]. You get the characters from start up to, but not including, stop. Leave out start to begin at the beginning. Leave out stop to go to the end. Step is how far to jump each time (default 1).

Animated explainer: Slicing a[6:10] step by step

  1. Here is the string with its index numbers. Positive numbers count from the left starting at 0. Negative numbers count from the right starting at -1.
  2. Take index 6 ("S"). This is the start position.
  3. Take index 7 ("h"). Then jump 1 step.
  4. Take index 8 ("a"). Then jump 1 step.
  5. Take index 9 ("r"). Then jump 1 step.
  6. We stop before index 10, because the stop position is never included. The result is "Shar".

Animated explainer: Slicing with a step: message[0:18:2]

  1. Here is the string with its index numbers. Positive numbers count from the left starting at 0. Negative numbers count from the right starting at -1.
  2. Take index 0 ("P"). This is the start position.
  3. Take index 2 ("t"). Then jump 2 steps.
  4. Take index 4 ("o"). Then jump 2 steps.
  5. Take index 6 (" "). Then jump 2 steps.
  6. Take index 8 ("r"). Then jump 2 steps.
  7. Take index 10 ("g"). Then jump 2 steps.
  8. Take index 12 ("a"). Then jump 2 steps.
  9. Take index 14 ("m"). Then jump 2 steps.
  10. Take index 16 ("n"). Then jump 2 steps.
  11. We stop before index 18, because the stop position is never included. The result is "Pto rgamn".

Easy tip

Slicing never gives an index error. If stop is past the end, Python just stops at the end. "Python"[2:100] is "thon".

Think of it like this

Think of the index numbers as sitting between the characters, like the marks on a ruler. s[2:5] cuts at mark 2 and mark 5 and gives you what is in between: 3 characters. This is why stop is not included, and why, with a step of 1, stop - start is the length of the slice (when stop is inside the string).

Strings are immutable

Immutable means cannot be changed after it is created. You cannot replace one character inside a string.

So methods that change text, like upper() and replace(), give you a new string and leave the original alone. This example from your course notebook shows it clearly.

Trap! Forgetting to store the result

Writing name.upper() on its own line does nothing useful. The new uppercase string is created and thrown away. Write name = name.upper() to keep it.

Changing case

Easy tip

Text comparisons are case-sensitive: "Delhi" == "delhi" is False. Before comparing or counting text from users or files, make it all lowercase with .lower().

Cleaning: strip and replace

strip() removes characters from both ends only. With no argument it removes spaces, tabs and new lines. lstrip() cleans the left end, rstrip() the right end.

Trap! strip() never touches the middle

strip() only works on the ends. To remove a character everywhere, use replace("$", "").

split() and join()

split() breaks a string into a list of pieces. join() does the opposite: it glues a list of strings together. These two are used constantly when reading data files.

Trap! join() only joins strings

The glue goes before .join, and the list must hold only strings.

Searching inside a string

Easy tip

The PDF says text.count("a") is 4. Run it and you get 5. "amazing" has two a's, and "and", "easy" and "learn" have one each. Always run the code yourself. The output is the truth.

find() vs index()

Both return the position. When the text is not found, find() returns -1 but index() raises an error. Use find() (or in) when the text might be missing.

Key takeaways

  • Indexes start at 0. Negative indexes count from the end: s[-1] is the last character.
  • Slicing s[start:stop:step] includes start, excludes stop. s[::-1] reverses.
  • Strings are immutable. Methods return a new string, so store it: s = s.strip().
  • strip() cleans only the ends. replace() changes everywhere.
  • split() turns text into a list. ", ".join(list) turns a list back into text.
  • find() returns -1 when missing. index() raises an error.

Flashcards

What is the index of the first and last character?
First: 0. Last: -1 (or len(s) - 1).
What does s[2:5] return?
The characters at index 2, 3 and 4. Stop (5) is never included.
How do you reverse a string?
s[::-1]
What does immutable mean for strings?
A string cannot be changed in place. s[0] = "X" is an error. Methods return a new string.
Why does name.upper() alone not change name?
It returns a new string. You must store it: name = name.upper().
strip() vs replace()
strip() removes characters only from the two ends. replace(old, new) changes every match anywhere.
capitalize() vs title()
capitalize(): capital first letter, every other letter small ("raman Sharma" becomes "Raman sharma"). title(): capital first letter of every word.
What do split() and join() do?
"a,b".split(",") gives ['a', 'b']. ",".join(['a', 'b']) gives "a,b".
find() vs index() when text is missing
find() returns -1. index() raises ValueError.
How do you count a word ignoring case?
text.lower().count("data")
Does slicing past the end cause an error?
No. "Python"[2:100] just gives "thon". Only single indexes like s[100] raise IndexError.
