How to build any small program

  1. Describe it in plain words. "Users can see movies, book seats, cancel seats, and the data is saved."
  2. Choose the data structure first. What do you store, and how will you look it up? (Usually a dictionary.)
  3. List the actions and make each one a function: show_movies, book, cancel, save.
  4. Test each function with fixed values before adding input().
  5. Add the menu loop last: while True + if/elif + break.
  6. Handle bad input with try/except and clear messages.

Project 1: Movie ticket booking system

Your course notebook builds this with one big while True loop. Here it is rebuilt with functions, so each part is short and easy to test. The data is saved with pickle, so bookings survive a restart.

Slides: Movie ticket system: walkthrough

  1. Data first: one dictionary of movies.

    Each movie name is a key. Its value is another dictionary with the price and seats left.

  2. Action 1: book seats

    • Is the movie there? (in)
    • Are there enough seats? (if)
    • Reduce the seats, work out the bill
    • Return a message instead of printing, so it is easy to test

  3. Action 2: cancel seats

    The course rule: 50% refund. Add the seats back.

  4. Action 3: save and load

    pickle.dump on exit, pickle.load on start. If the file does not exist yet (FileNotFoundError), start from the default movies.

  5. Last: the menu loop

    while True, show the movies, ask for 1, 2 or 3, call the right function, break on exit. Because the logic lives in functions, the loop stays short and readable.

Easy tip

Run that cell twice in Jupyter and the seat counts keep going down, because the second run loads the saved file. That is the whole point of saving. Delete cinema.pkl to start fresh.

Spot the bug in the original

The course's cancel option adds seats back without checking how many were booked, so someone could "cancel" 100 seats that were never sold. A real system would track bookings per customer. Try adding that as an extra challenge: a dict of {customer: {movie: seats}}.

Check the indentation in your PDF copy

In the PDF's get_low_stock_items, the line return low_stock appears indented inside the for loop. If it is, the method returns after checking only the first item. The return must line up with the for, as in low_stock() above. Indentation is logic in Python.

Key takeaways

  • Plan the data structure first, then turn each action into a function.
  • Test functions with fixed values before adding input() and menus.
  • Save state with pickle (or JSON) so it survives a restart.
  • Use each collection for its strength: dict for lookup, set for unique, list for history, tuple for fixed facts.
  • Indentation is logic: a misplaced return changes what a function does.

Chapter quiz

  1. In the movie system, why do book() and cancel() return a message instead of printing it?

    1. Printing is slower
    2. Returned values are easy to test and reuse
    3. print() does not work in functions
    4. Pickle needs strings
    Answer

    Returned values are easy to test and reuse. A returned message can be printed, logged or checked in a test.

  2. Why does load_db() catch FileNotFoundError?

    1. To delete old files
    2. The first time the program runs, no save file exists yet, so it starts with default data
    3. Pickle always raises it
    4. To speed up loading
    Answer

    The first time the program runs, no save file exists yet, so it starts with default data. Without it, the very first run would crash.

  3. Which collection does the inventory system use for categories, and why?

    1. list, to keep order
    2. set, so each category is stored only once
    3. tuple, so it cannot change
    4. dict, for fast lookup
    Answer

    set, so each category is stored only once. A set ignores duplicates automatically.

  4. Why are an item's name, category and price stored in a tuple?

    1. Tuples are the only type pickle can save
    2. They are fixed facts that should not change by accident
    3. Tuples allow duplicates
    4. Tuples are sortable
    Answer

    They are fixed facts that should not change by accident. Immutability protects data that should stay fixed.

  5. What goes wrong if return result is indented inside the for loop of low_stock()?

    1. Nothing
    2. It returns after checking only the first item
    3. It raises IndentationError
    4. It returns None
    Answer

    It returns after checking only the first item. return ends the function the first time it runs, which would be during the first loop round.

  6. In the theater program, what happens when the user types "five" for the number of tickets?

    1. The program crashes
    2. int() raises ValueError, the except block prints a message, and the loop asks again
    3. It books 5 tickets
    4. It books 0 tickets
    Answer

    int() raises ValueError, the except block prints a message, and the loop asks again. That is the while True + try/except validation pattern.
