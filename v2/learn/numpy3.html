NumPy extras: iterate, split, search, random and ufuncs

The rest of the NumPy toolbox: loop over arrays, cut them into pieces, find values, make random data that behaves like real data, and use NumPy's fast maths functions (ufuncs).

In this chapter you will learn

  • Loop over arrays with for, nditer and ndenumerate
  • Split arrays with array_split, split, vsplit and hsplit
  • Find values with np.where and np.searchsorted
  • Make random numbers and simulate data with distributions
  • Use ufuncs for arithmetic, rounding, logs, sums, LCM/GCD, trigonometry and sets

Looping over arrays

You rarely need loops in NumPy, because maths on the whole array is faster. When you do, a for loop over a 2D array gives you one row at a time.

Easy tip

Before you write a loop, ask: can NumPy do this on the whole array at once? Usually it can, and it is much faster.

Splitting arrays

Splitting is the opposite of joining with concatenate. np.array_split(a, n) cuts an array into n parts. If the parts cannot be equal, the first ones get one extra item.

Animated explainer: How array_split shares out 7 values

  1. 7 values into 3 parts. 7 ÷ 3 = 2, with 1 left over.
  2. Every part gets 2 values. The 1 left over goes to the first part, so part 1 gets 3 values: [1 2 3].
  3. Part 2 gets the next 2: [4 5].
  4. Part 3 gets the last 2: [6 7]. The sizes are 3, 2 and 2. np.split(a, 3) would stop with a ValueError instead.

Predict the output

  1. [3, 3, 2, 2]
  2. [2, 2, 3, 3]
  3. [3, 3, 3, 1]
  4. A ValueError
Answer

[3, 3, 2, 2]. 10 ÷ 4 = 2 with 2 left over. The first two parts get one extra each: 3, 3, 2, 2.

Searching arrays

np.where(condition) gives the positions where the condition is True. np.searchsorted(a, x) tells you where x would go in a sorted array to keep it sorted.

Animated explainer: searchsorted: where does 300 fit?

  1. prices is sorted. Where could 300 go so that it stays sorted?
  2. 100 and 250 are smaller than 300, so 300 must come after them.
  3. 400 is the first value bigger than 300, so 300 goes at position 2, just before 400.
  4. Put there, the array stays sorted. Analysts use this to put values into bands, like price ranges. If the value is already in the array, side="right" places it after the equal value instead of before it.
Trap!

np.where(cond) with one argument gives positions. np.where(cond, x, y) with three arguments picks values, as you saw in the last chapter. Same name, two different jobs.

Random numbers

np.random makes random data for testing code, simulations and sampling. np.random.seed(n) makes the "random" numbers repeat exactly, so your results are the same every run.

Easy tip

Newer code often uses a generator object: rng = np.random.default_rng(42), then rng.integers(1, 7, 10) or rng.normal(0, 1, 5). It does the same jobs and is the modern recommendation.

Random data distributions

A distribution describes which values are likely and which are rare. Analysts use them to simulate data and to recognise patterns in real data. Each example below makes 100,000 values, so the averages come out very close to the theory.

Slides: Which distribution fits my data?

  1. A distribution is the shape your data makes when you count it.

    Count how many values fall into each range and draw the counts as bars: a histogram. Its shape tells you which distribution fits. Every chart here is 100,000 simulated values.

  2. Normal: the bell curve

    Most values sit near the average and fewer sit far away, on both sides. Test scores, delivery times, heights.

  3. Binomial: successes out of n tries

    10 guests, and each one orders breakfast with a chance of 0.4. On most days about 4 of them do. It can never go above 10.

  4. Poisson: events in a time window

    Bookings per day, 6 on average. Never negative, with a long tail to the right (the highlighted busy days).

  5. Uniform: every value equally likely

    A random price between 100 and 200. Flat: no value is more likely than another.

  6. Exponential: waiting time until the next event

    Minutes between two bookings, 10 on average. Short waits are common and long waits are rare.

  7. How to choose

    • Measuring something, like a time or a score? Try normal.
    • Counting successes out of a fixed number of tries? Binomial.
    • Counting events in a time window? Poisson.
    • Measuring the wait between events? Exponential.
    • No value more likely than another? Uniform.

ufuncs: NumPy's fast maths functions

A ufunc (universal function) works on every value of an array at once, in fast compiled code. You have already used some: a + b is really np.add(a, b).

Predict the output

  1. [1. 2. 3.]
  2. [0. 2. 2.]
  3. [0. 1. 2.]
  4. [1. 2. 2.]
Answer

[0. 2. 2.]. A .5 goes to the nearest even number, exactly like Python's round(). Always rounding .5 up would push totals higher over many values.

Practice

  1. stays = np.array([2, 1, 3, 2, 4, 1, 2]) holds a week of guest stays. Split it into 3 parts with array_split and print the total nights in each part as a list: [6, 6, 3].

    Hint

    Loop over np.array_split(stays, 3) and collect int(part.sum()).

    Solution

    7 values in 3 parts gives sizes 3, 2 and 2. The first part gets the extra value.

  2. rates = np.array([1800, 2600, 1800, 4800, 2600]). Print the positions where the rate is 2600, then where 3000 would fit into the sorted unique rates.

    Hint

    np.where(rates == 2600)[0], then np.searchsorted(np.unique(rates), 3000).

    Solution

    np.unique also sorts, which is exactly what searchsorted needs.

  3. Simulate 100,000 days of bookings with np.random.poisson(lam=6, ...) after np.random.seed(5). Print the average bookings per day (rounded) and the share of days with 10 or more bookings (2 decimals).

    Hint

    round(days.mean()) and round(np.mean(days >= 10), 2).

    Solution

    With so many days, the simulation lands very close to the theory: about 8% of days get 10 or more bookings.

  4. occupancy = np.array([60, 66, 72, 70]) is a hotel's weekly occupancy %. Print the week-to-week change with np.diff, then the running total with np.cumsum.

    Hint

    Both are ufunc helpers: np.diff(occupancy) and np.cumsum(occupancy).

    Solution

    diff gives one value fewer than the input, because it compares neighbours.

  5. Guest IDs from two weeks: week1 = np.array([101, 102, 103, 105]) and week2 = np.array([102, 105, 106]). Print the guests who came in both weeks, the guests who came only in week 1, and everyone.

    Hint

    np.intersect1d, np.setdiff1d and np.union1d.

    Solution

    These work like Python's set operators &, - and |, and they return sorted arrays.

Real data practice: hotel bookings

The same messy **hotel_bookings.csv file, and two everyday analyst jobs: putting values into bands, and sharing work out fairly**.

  1. Put every booking's room rate into a price band: Budget (under ₹2,000), Mid (₹2,000 to ₹2,999) and Premium (₹3,000 and up). Use np.searchsorted with the edges [2000, 3000] and print how many bookings are in each band.

    Hint

    np.searchsorted([2000, 3000], rates, side="right") gives 0, 1 or 2 for every booking. Then count with np.sum(bands == i).

    Solution

    side="right" sends a value that equals an edge to the higher band, so a rate of exactly ₹2,000 counts as Mid. This is how analysts bucket prices, ages or scores.

  2. Three staff members will phone every booking to confirm it. Share the unique bookings out with np.array_split, in file order, and print how many calls each person gets and their first and last booking ID.

    Hint

    Make an array of booking_id values, then loop over np.array_split(ids, 3) with enumerate(..., start=1).

    Solution

    40 bookings do not split equally into 3, so np.split would fail. array_split gives the first person the one extra call.

Key takeaways

  • Loop over arrays only when you must. nditer visits every value, ndenumerate also gives its position.
  • array_split allows unequal parts. split needs equal parts or raises ValueError.
  • np.where(cond) gives positions. np.searchsorted finds where a value fits in a sorted array.
  • np.random.seed() makes random results repeat. Distributions (normal, binomial, poisson, uniform...) simulate realistic data.
  • ufuncs work on whole arrays at once: arithmetic, rounding, logs, cumsum, diff, lcm, sin, set operations.

Flashcards

array_split vs split
array_split allows unequal parts. split needs equal parts, or it raises ValueError.
vsplit vs hsplit
vsplit cuts a table into groups of rows. hsplit cuts it into groups of columns.
np.where(cond) with one argument
Gives the positions where the condition is True.
What does np.searchsorted(a, x) do?
Finds the position where x would go in the sorted array a.
Why use np.random.seed()?
To make random results the same every run.
Normal vs Poisson vs Binomial
Normal: bell curve (scores, times). Poisson: counts per time window (bookings per day). Binomial: successes out of n tries.
What is a ufunc?
A NumPy function that works on every value of an array at once, like np.add or np.sqrt.
np.floor vs np.ceil vs np.trunc
floor goes down, ceil goes up, trunc cuts the decimals off (towards 0).
What does np.around([0.5, 1.5, 2.5]) give?
[0. 2. 2.]: a .5 goes to the nearest even number, like Python's round().
permutation vs shuffle
np.random.permutation(a) returns a new shuffled copy. np.random.shuffle(a) shuffles a itself and returns None.
np.cumsum vs np.diff
cumsum gives running totals (same length). diff gives the change between neighbours (one value shorter).
intersect1d vs setdiff1d vs union1d
In both / only in the first / in either. All three return sorted unique values.
